[1] AI内心风景共创系统设计案
[2] 1. 系统目标
[3] 本系统通过AI引导用户将当下感受转化为一个结构化的环境场景。
[4] 用户首先使用一个词描述当下感受，再根据这个词想象一个地点。AI随后通过动态提问，逐步补全场景中的环境条件、声音和空间结构。
[5] 系统最终输出：
[6] 用户可阅读和确认的场景摘要；
[7] 结构化场景JSON；
[8] 2D图像生成Prompt；
[9] VR环境生成配置；
[10] 环境声音生成Prompt；
[11] 完整对话记录；
[12] 用户修改和确认记录；
[13] 一个包含所有结果文件的项目文件夹。
[14] AI只负责提问、整理和视觉转译，不判断用户的心理状态，也不为地点、季节、天气、颜色或空间结构赋予固定心理意义。
[16] 2. 目标用户流程
[17] 用户完整流程为：
[18] 打开系统首页；
[19] 可选：进入设置页面配置API；
[20] 点击“开始创作”；
[21] 用一个词描述当下感受；
[22] 根据这个词想象一个地方；
[23] 与AI继续对话，补全环境；
[24] 查看AI整理的场景摘要；
[25] 修改或确认摘要；
[26] 生成结构化结果文件；
[27] 查看输出结果和保存位置。
[28] 系统第一版不需要直接生成完整VR场景，但应输出能够供后续2D和VR生成模块使用的标准化配置。
[30] 3. 前端页面结构
[31] 3.1 首页
[32] 首页应尽量简单，避免让用户在开始前看到大量技术设置。
[33] 页面顶部
[34] 左侧：
[35] 系统名称；
[36] 简短说明。
[37] 例如：
[38] 将当下的感受，慢慢变成一个可以看见和进入的地方。
[39] 右侧：
[40] 设置按钮；
[41] 历史项目按钮，可选；
[42] 帮助按钮，可选。
[43] 页面主体
[44] 主体区域包含：
[45] 标题
[46] 创建你的内心风景
[47] 简短说明
[48] AI会通过几个简单问题，帮助你把一个词慢慢转化为一个完整环境。
[49] 主要按钮
[50] 开始创作
[51] 次要按钮
[52] 打开已有项目
[53] “打开已有项目”适合桌面应用或支持本地文件访问的版本。
[54] 首页底部说明
[55] 使用简短文字说明：
[56] 这里没有正确答案；
[57] 系统不会诊断用户；
[58] 用户可以跳过任何不想回答的问题；
[59] 所有场景意义由用户自己决定。
[61] 3.2 设置按钮
[62] 设置按钮使用较小的齿轮图标，位于首页右上角。
[63] 点击后打开侧边抽屉或模态窗口。
[64] 设置内容分为四组：
[65] API设置；
[66] 模型设置； 3.生成设置；
[67] 文件保存设置。
[69] 4. 设置页面设计
[70] 4.1 API Key
[71] 字段名称：
[72] OpenAI API Key
[73] 组件：
[74] 密码输入框；
[75] 显示或隐藏按钮；
[76] 测试连接按钮；
[77] 清除按钮。
[78] 状态提示：
[79] 尚未设置；
[80] 正在验证；
[81] 连接成功；
[82] API Key无效；
[83] 网络连接失败。
[84] 安全要求
[85] API Key不应直接写入源代码，也不应保存到普通日志文件。
[86] 对于研究原型，可以提供两种保存方式：
[87] 仅本次使用
[88] API Key只保存在当前内存；
[89] 页面关闭后自动清除；
[90] 默认推荐。
[91] 保存在本机
[92] 仅适用于Electron或其他桌面应用；
[93] 使用操作系统安全凭据存储；
[94] 不应使用普通文本文件保存。
[95] 如果是普通浏览器Web应用，不建议让浏览器直接向OpenAI发送长期API Key。更安全的正式架构是由后端保存密钥，并由前端请求自己的后端接口。
[96] 如果研究原型明确采用“用户自带API Key”，页面必须显示：
[97] API Key只用于调用所选模型。建议仅在本机研究环境中使用，不要在公共设备上保存。
[99] 4.2 模型选择
[100] 字段名称：
[101] 对话模型
[102] 使用下拉菜单。
[103] 系统不应在代码中长期写死模型列表。可以通过OpenAI的Models接口读取当前账号可访问的模型，再过滤出允许的GPT文本模型。OpenAI提供模型列表接口，因此应用可以根据API Key动态读取可用模型。
[104] 建议同时允许：
[105] 自动获取模型；
[106] 手动输入模型ID；
[107] 保存最近使用的模型。
[108] 模型列表中可以显示：
[109] 模型ID；
[110] 是否支持所需参数；
[111] 推荐用途；
[112] 最近一次验证时间。
[113] 系统不应默认认为所有模型都支持完全相同的参数，因为不同模型对参数的支持可能不同。
[115] 4.3 Temperature
[116] 字段名称：
[117] Temperature
[118] 组件：
[119] 滑块；
[120] 数字输入框；
[121] 推荐值提示。
[122] 建议范围：
[123] 0.0–1.0；
[124] 默认值0.4。
[125] 推荐说明：
[126] 0.0–0.2：更稳定、更严格；
[127] 0.3–0.5：适合本系统；
[128] 0.6–1.0：表达更多样，但可能加入较多未经用户确认的细节。
[129] 本系统的核心Agent需要稳定提取用户信息，因此不建议设置过高。
[130] 如果所选模型不支持temperature，界面应：
[131] 自动禁用该字段；
[132] 显示“当前模型不支持此参数”；
[133] 不向API请求中发送temperature。
[135] 4.4 输出位置
[136] 字段名称：
[137] 项目保存位置
[138] 组件：
[139] 当前目录显示框；
[140] 选择文件夹按钮；
[141] 恢复默认按钮。
[142] 默认位置可以为：
[143] Documents/InnerLandscape/
[144] 每次创建项目时，自动生成单独文件夹：
[145] InnerLandscape/
└── 2026-07-28_104500_fog_coastal_station/
[146] Web版本限制
[147] 普通浏览器通常不能自由写入用户任意本地目录。
[148] Web版本可以采用：
[149] 用户完成后下载ZIP；
[150] 使用浏览器支持的文件系统选择器；
[151] 使用后端服务器保存。
[152] Electron桌面版
[153] Electron版本可以直接让用户选择本地输出文件夹，并在项目完成后自动写入文件。
[154] 因此，如果“用户选择文件保存位置”是核心需求，优先推荐Electron桌面应用。
[156] 5. 创作页面UI
[157] 5.1 页面整体布局
[158] 推荐三栏结构。
[159] 左侧：进度和检查清单
[160] 宽度约20%。
[161] 显示六个信息模块：
[162] 感受关键词；
[163] 场景基础；
[164] 环境氛围；
[165] 声音环境；
[166] 空间结构；
[167] 重要细节。
[168] 每一项有三种状态：
[169] 未开始；
[170] 信息不足；
[171] 已完成。
[172] 用户看到的是简化状态，不需要看到Agent内部的详细评分。
[173] 示例：
[174] ✓ 感受关键词
✓ 场景基础
● 环境氛围
○ 声音环境
○ 空间结构
○ 重要细节
[175] 其中：
[176] ✓ 已完成；
[177] ● 正在进行；
[178] ○ 尚未完成。
[179] 中间：AI对话区域
[180] 宽度约55%。
[181] 包含：
[182] AI消息；
[183] 用户消息；
[184] 文本输入框；
[185] 发送按钮；
[186] 跳过按钮；
[187] 返回上一步按钮，可选。
[188] 输入框提示：
[189] 写下你首先想到的内容，不需要很完整。
[190] 第一版以文字输入为主。语音输入可以作为后续功能。
[191] 右侧：实时场景摘要
[192] 宽度约25%。
[193] 展示AI当前已经提取的信息。
[194] 例如：
[195] 感受关键词
雾

地点
海边的旧火车站

季节与时间
深秋，黄昏

天气与光线
小雨、薄雾、较暗

声音
尚未确定
[196] 每个字段旁边提供：
[197] 编辑；
[198] 删除；
[199] 锁定。
[200] “锁定”表示AI后续不得自行改变该字段。
[202] 5.2 移动端或窄屏布局
[203] 窄屏下采用：
[204] 顶部进度条；
[205] 中间对话；
[206] 底部可展开的“当前场景”面板。
[207] 第一版主要面向研究环境，建议优先桌面端。
[209] 6. 固定核心问题
[210] 系统包含十个核心问题，但并不要求按顺序逐题提问，也不要求每个问题都独立出现。
[211] Q1 感受关键词
[212] 如果用一个词形容你当下的感受，会是什么？
[213] 辅助说明：
[214] 可以是情绪、颜色、天气、质感、声音，或任何首先想到的词。
[215] Q2 地点联想
[216] 想到“{关键词}”，你会想象出什么地方？
[217] Q3 季节与时间
[218] 这里是什么季节和时间？
[219] Q4 天气与光线
[220] 这里的天气和光线是什么样的？
[221] Q5 声音
[222] 这里能听到什么声音？
[223] Q6 开放性与可见范围
[224] 这个地方是开阔的还是封闭的？能看到多远？
[225] Q7 路径与出口
[226] 这里有没有一条路、入口或出口？它通向哪里？
[227] Q8 空间连接
[228] 这是一个连续的空间，还是由几个分开的区域组成？
[229] Q9 重要物件
[230] 这里有没有一个特别重要的物件？
[231] Q10 必须出现和排除内容
[232] 还有什么一定要出现，或者一定不要出现？
[234] 7. Agent核心架构
[235] 推荐使用一个主要对话Agent，加一个确定性的状态管理模块。
[236] 不建议完全依赖语言模型自己记住哪些问题已经回答，因为这可能造成：
[237] 重复提问；
[238] 遗漏字段；
[239] 已确认内容被修改；
[240] 用户一次回答多个问题时无法正确更新；
[241] 对模糊信息过早标记完成。
[242] 整体架构为：
[243] 用户消息
   ↓
信息提取器
   ↓
场景状态更新
   ↓
完整度检查
   ↓
追问决策器
   ↓
生成下一条AI回复
[245] 8. Agent检查清单
[246] 内部检查清单包括六个模块。
[247] 8.1 感受关键词
[248] 字段：
[249] feeling_keyword
[250] 完成标准：
[251] 至少存在一个用户认可的词或短语；
[252] 可以是情绪、颜色、天气、声音或抽象描述；
[253] 不要求必须是传统情绪词。
[254] 完成示例：
[255] 雾；
[256] 空；
[257] 蓝色；
[258] 疲惫；
[259] 漂浮；
[260] 像一直在等。
[261] 未完成示例：
[262] 不知道；
[263] 随便；
[264] 没想法。
[265] 如果用户不愿命名，可以允许：
[266] {
  "value": "unnamed",
  "status": "skipped_by_user"
}
[267] 此时仍可以继续场景创建。
[269] 8.2 场景基础
[270] 字段：
[271] place
[272] season
[273] time_of_day
[274] 最低完成标准：
[275] 地点必须足以生成一个基本环境；
[276] 季节和时间可以明确，也可以由用户标记为“不确定”；
[277] 不允许由AI未经许可强制补充。
[278] 地点足够具体的例子：
[279] 海边的旧火车站；
[280] 冬天的森林；
[281] 没有窗户的房间；
[282] 一座漂浮在云上的小岛。
[283] 地点不足的例子：
[284] 一个地方；
[285] 外面；
[286] 不知道；
[287] 有点空。
[288] 如果地点不足，Agent应追问。
[290] 8.3 环境氛围
[291] 字段：
[292] weather
[293] lighting
[294] 完成标准：
[295] 天气明确，或用户明确表示没有特别天气；
[296] 光线能够支持视觉生成；
[297] 可以从时间和天气中推导，但必须标记为“推导值”。
[298] 例如用户说：
[299] 深夜，正在下小雨。
[300] 系统可推导：
[301] {
  "lighting": {
    "value": "dim",
    "source": "system_inference",
    "needs_confirmation": true
  }
}
[302] 不能直接视为用户确认。
[303] Agent可以问：
[304] 我暂时理解为整体光线较暗，这符合你的想象吗？
[305] 用户确认后才标记完成。
[307] 8.4 声音环境
[308] 字段：
[309] sound_sources
[310] overall_sound_level
[311] 最低完成标准：
[312] 至少明确一个声音来源；
[313] 或用户明确选择“几乎没有声音”。
[314] 不强制询问每个声音的强度和频率。
[315] 如果用户主动描述：
[316] 偶尔能听到远处的火车声。
[317] 系统自动提取：
[318] 来源：火车；
[319] 距离：远处；
[320] 频率：偶尔。
[321] 若用户只回答：
[322] 有声音。
[323] 则信息不足，需要追问：
[324] 最明显的是什么声音？
[326] 8.5 空间结构
[327] 字段：
[328] openness
[329] visibility
[330] path_or_exit
[331] connectivity
[332] 最低完成标准：
[333] 开放性与可见范围
[334] 至少明确：
[335] 开放、半开放或封闭；
[336] 可见范围是否受到限制。
[337] 路径与出口
[338] 至少明确：
[339] 有或没有；
[340] 如果有，大致通向哪里或呈现什么状态。
[341] 空间连接
[342] 至少明确：
[343] 连续空间；
[344] 或多个被分隔的区域。
[345] 不要求所有字段都非常详细，但必须足以生成稳定一致的VR布局。
[347] 8.6 重要细节
[348] 字段：
[349] important_objects
[350] required_elements
[351] excluded_elements
[352] 完成标准：
[353] 用户明确说明是否存在重要物件；
[354] 用户有机会说明必须出现和不得出现的内容。
[355] 允许空数组：
[356] {
  "important_objects": [],
  "required_elements": [],
  "excluded_elements": []
}
[357] 空数组表示用户确认“没有”，而不是Agent尚未询问。
[359] 9. 字段状态设计
[360] 每个字段不只是保存值，还要保存状态和来源。
[361] 推荐格式：
[362] {
  "value": "薄雾",
  "status": "confirmed",
  "source": "user_explicit",
  "confidence": 1.0,
  "locked": false,
  "needs_follow_up": false
}
[363] 9.1 status
[364] 可用值：
[365] missing
[366] partial
[367] inferred
[368] confirmed
[369] skipped_by_user
[370] not_applicable
[371] 9.2 source
[372] 可用值：
[373] user_explicit
[374] user_implicit
[375] agent_inference
[376] agent_suggestion
[377] user_confirmed_agent_suggestion
[378] 9.3 locked
[379] 用户在右侧摘要中锁定某项后：
[380] {
  "locked": true
}
[381] Agent不得再改变该内容，除非用户主动修改。
[383] 10. 用户一次回答多个问题的处理
[384] Agent每收到一条用户消息，都必须对完整检查清单进行重新提取，而不是只分析当前所问字段。
[385] 例如AI问：
[386] 想到“雾”，你会想象出什么地方？
[387] 用户回答：
[388] 深秋傍晚的海边车站，正在下小雨，远处有海浪声，铁轨一直通到雾里。
[389] 系统应一次提取：
[390] 地点：海边车站；
[391] 季节：深秋；
[392] 时间：傍晚；
[393] 天气：小雨和雾；
[394] 声音：远处海浪；
[395] 路径：铁轨；
[396] 路径状态：延伸进雾中；
[397] 可见范围：受到雾限制。
[398] 然后跳过已经完成的问题。
[399] 下一问可能直接是：
[400] 这个车站整体是开阔的，还是比较封闭的？
[401] 而不应重复问季节、天气或声音。
[403] 11. Agent完整度判断
[404] 每个模块设置三个等级。
[405] Level 0：缺失
[406] 无法支持场景生成。
[407] 例如：
[408] 地点：一个地方
[409] Level 1：基本足够
[410] 能够生成，但仍有少量歧义。
[411] 例如：
[412] 地点：海边车站
[413] Level 2：充分
[414] 能够生成清晰且较稳定的环境。
[415] 例如：
[416] 地点：靠近海岸的旧式小型火车站，站台直接面向海面
[417] Agent追问逻辑：
[418] Level 0：必须追问；
[419] Level 1：根据整体缺失情况决定是否追问；
[420] Level 2：不再追问；
[421] 用户明确不想回答：标记跳过，不再追问。
[422] 第一版不需要向用户显示Level数值。
[424] 12. 下一问题选择算法
[425] Agent每轮完成状态更新后执行以下流程：
[426] Step 1：检查是否有矛盾
[427] 例如：
[428] 完全封闭，但能看到无限远；
[429] 深夜，但出现强烈正午阳光；
[430] 用户要求绝对安静，但又要求雷暴声；
[431] 不允许建筑，但地点是室内车站。
[432] 如果存在矛盾，优先确认矛盾。
[433] 提问方式：

[649] 26. 核心系统原则
[650] AI检查完整清单，但不机械逐题询问。

[655] Agent不得解释用户心理。
[656] AI推导内容必须标记来源并由用户确认。

[659] 原始回答、结构化结果和修改历史分别保存。
[660] API Key不得写入项目输出文件。
